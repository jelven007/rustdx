## 可复跑的严格验收工具

- [Rust 验收示例](../../../crates/rustdx-core/examples/validate_quote_push.rs)：默认要求整个观察窗口处于同一交易日的同一交易会话。日历越界、周末、节假日、午休、跨午休或收盘都不能通过门禁。
- [Python 独立核验](../../../scripts/validation/verify_quote_push.py)：仅使用标准库，重解帧头、zlib、0547 XOR、带符号整数、实际目录精度和五档；复查请求轨迹、前置通知、基线与最终状态，以及每个有效变化判定。
- [订阅传输回归](../../../crates/rustdx-core/tests/quote_subscription.rs)：覆盖被动多证券更新、部分基线、完整五档替换、重复与空通知、半帧超时、消息号复用、错误帧、游标回退、断开、预算和连接许可释放。

工具保留请求与响应的完整二进制、解压前后正文、XOR 正文、推送 DTO、接收时间、事件序号、连接标识和请求计数。推送没有伪造的请求文件。预算为最多 8,192 个事件、64 MiB 存储；观察时长限制为 30–600 秒，默认 180 秒。

本工具采用以下通过条件：

1. 实际网络运行，整个被动观察窗口处于严格交易日历覆盖内的同一交易会话，基线覆盖全部订阅证券。
2. 观察期间不重建会话，连接与订阅代次保持一致；被动阶段请求数为 0，包括心跳。
3. 至少收到两帧完整 0547 更新；接收时间均晚于基线完成 5 秒。
4. 每个有效帧至少有一个证券的游标严格推进，且已知价格、成交量、成交额或五档内容发生变化。

仅游标变化、状态或不透明尾部变化、重复通知、空通知及基线前已排队通知均不满足有效推送条件。消息号允许复用基线消息号：被动阶段没有在途请求，不能仅因消息号相同拒绝推送。

五秒隔离期和连续变化用于降低基线附近缓存通知造成的误判；它不证明交易所事件时间、最大推送延迟或长期可靠性。本次独立重解使用已采样的每证券 46 字节尾部布局，遇到其他布局会拒绝核验，需补充真实样本后再扩展。

`--allow-closed` 明确进入诊断模式，任何结果都不能成为 `passed`。示例只有盘中验收通过才返回退出码 0；未验收或诊断结果返回 2。离线核验脚本退出码 0 只代表证据核验成功，须同时读取其 `live_trading_push_verified` 和 `business_status`。
