核对日期：2026-10-24。项目快照为 `HEAD=408e30eb172704070e384fb35fb0e56549a1fbc5` 的当前工作区，包含既有未提交修改；核心库版本 1.12.2，Rust 2024 / MSRV 1.89。基线为已校验发布包的 [eltdx 3.2.2 22 命令手册](../operations/ELTDX_3_2_2_COMMAND_GUIDE_20261024.md)，包括 2 项会话和 20 项业务命令。[cite:1](#cite-1)

## 1. 统计口径与结论

| 口径 | 数量 | 含义 |
| --- | ---: | --- |
| 同码 | 9 | 有相同 opcode 的实际请求及解析 / 初始化路径 |
| 替代 | 4 | 业务相近，但使用旧版或其他命令 |
| 未接入 | 9 | 没有该命令的主动请求、业务解析和公开调用链 |
| 合计 | 22 | 每个基线项只统计一次 |
| 排除会话后的业务能力 | 11 / 20 | 具备基础或相近业务，仍不等于 11 项完整合同 |

当前项目正常调用路径共有 **15 个不同 opcode**：

```text
000d 000f 0010 02c5 02cf 02d0 044e 0450
051d 052d 053e 06b9 0fb4 0fb5 0fc5
```

其中 `02c5/02cf/02d0` 为板块元信息 / 旧 F10，`0450/051d/0fb5` 为旧目录 / 当日分时 / 历史明细，均不在这份 22 命令清单中。因此 15÷22 不能作为兼容率；基础能力比例也不衡量字段完整性或生产验收。[cite:2](#cite-2)

最初分析时[九命令计划](../development/NINE_COMMANDS_IMPLEMENTATION_20261024.md)尚未实施；后续已完成九项源码，正文的缺口与计数仅属于该历史快照，最新覆盖以页首实施记录为准。

## 3. 已有接口的字段与语义差异

### 3.1 会话：可初始化与探活，缺少结构化结果和自动保活

当前新连接 / 重连自动发送 `000d` 的 PACK1，是基础握手能力。实现读取完整响应帧，但没有将正文解析成 `server_datetime/server_name/session_minutes/product_tag`；也没有按基线的握手模型验证 / 提供这些字段。[cite:3](#cite-3)

`heartbeat()` 返回的是 `044e` 查询得到的深市证券数量，不是 `0004` 的 `HeartbeatAck(server_date)`。连接池的 health check 在借出空闲连接时触发；当日 IP 池每天 09:00 测速也不是对持有连接的周期心跳。

| 需求 | 当前情况 |
| --- | --- |
| 建连可用、故障转移 | 已有 |
| 重连自动初始化 | 已有 |
| 显式探活 | 已有，命令为 044e |
| 主站日期 / 身份 / 时段 | 未提供结构化结果 |
| 默认 30 秒空闲自动保活 | 未实现 |

### 3.2 证券目录：旧目录有有效字段，新目录合同未实现

当前 `SecurityListData` 已有 `code/name/volunit/decimal_point/pre_close`，不能说“完全没有目录精度和单位”。`stocks()` 先查数量，再分页，检查提前空页、重复证券、超过页长或总量；这是已有完整性防护。[cite:4](#cite-4)

| 维度 | eltdx 3.2.2 | 当前 rustdx |
| --- | --- | --- |
| 请求 / 记录 | 044d / 37 字节 | 0450 / 29 字节 |
| 页量 / 偏移 | 默认最大 1600 / u32 | 自动聚合每页最多 1000 / u16 |
| 市场 | API 可表达 sz/sh/bj | 高层普通 TCP 只允许 0/1 |
| 分类 | category/board/reason 派生属性 | DTO 无这些属性 |
| 元数据精度应用 | 行情 / 分时按证券目录精度换算 | 报价和分时仍固定价格比例 |
| A 股计数 | 拉目录本地过滤 | 有 Symbol::is_a_share，未封装目录计数 |

`Symbol` 能表示北交所，且有本地 A 股分类，不代表 TCP 已允许北交所。这里的 board 是上市板块分类，仍不同于概念板块 / 行业所属关系。

### 3.3 旧五档：核心盘口已有，精度和状态信息未完整暴露

`QuoteData` 已返回现价、昨收、OHLC、总量 / 当前量、成交额、内外盘、五档价量，以及服务器时间文本、涨速和派生涨跌幅；checked 解析器验证返回身份、重复、数量、尾部及基本值。[cite:5](#cite-5)

| 基线字段 / 行为 | 当前对应 | 差距 |
| --- | --- | --- |
| 价格、OHLC | price/last_close/open/high/low | 当前固定 /100，缺目录 decimal 驱动 |
| 累计 / 当前量、金额 | vol/cur_vol/amount | 单位需按品种确认 |
| 五档 | bid1..5 / ask1..5 及量 | 已有，当前不是缺五档 |
| trading_status_raw | 解析 u16 后丢弃 | 无停牌 / 状态语义输出 |
| open_amount、尾部 raw | 部分槽读后丢弃 | 无基线完整 raw 模型 |
| 活跃值 | active1/active2 读后丢弃 | 无保留字段 |
| 单次证券数 | 当前强制 1–80、拒绝重复 | 当前明确客户端策略；基线直接 legacy 并无 80 专用校验 |

因此保留当前 80 只策略是合理实现选择，不必为复制基线而取消校验；应注明它是本库边界。需要字段精度和状态完整性时，要补模型与解码，不能只加一个新方法名。

### 3.4 K 线：排序、区间、批量已有优势，增强协议合同仍缺

当前已有：

- 股票 / 指数各自的独立解码器，指数返回上涨 / 下跌家数。
- 单页 1–800 校验；日期、时间、OHLCV、截断、超量与多余字节校验。
- 区间分页结束后全局升序、按时间去重、闭区间过滤，拒绝不向历史推进的页。
- 多证券有界线程查询，各证券保留独立成功 / 失败结果。
- CanonicalBar 显式携带周期、来源、价格口径，调用者明确指定 VolumeUnit。
- 本地日线 Qfq/Hfq，使用类别 1 权息事件，价格调整但保留量额。[cite:6](#cite-6)

| 对比点 | 基线 | 当前项目 | 分析 |
| --- | --- | --- | --- |
| 日线编号 | day=4/1 | Period::Day=9，低层也允许 4 | 已有样本证明单位不同，不能互抄数字 |
| 1 分钟 | 7/1 | Period::Minute1=8 | 当前没有 N 周期参数；8 在基线为 N 分钟 |
| 自定义周期 | Nm / Nd / Ns | category≤11、参数固定 | 不能仅靠 category=8/9 表示增强周期合同 |
| 请求长度 | 54 字节 | 38 字节 | 同 opcode 不等于同布局 / 功能 |
| 复权 | 服务器 none/qfq/hfq/fixed 两种 | 本地日线 Qfq/Hfq | 原理、锚点、周期和覆盖范围不同 |
| 全量结束 | 空页；短页继续 | 短页或覆盖 begin 结束 | 需按旧服务端证据决定，不直接套新版规则 |
| 全局顺序 | 高层直接拼页，未全局排序去重 | 排序、去重、过滤 | 当前机制值得保留 |
| 偏移上限 | u16，默认 max_pages=200 | u16，最多 82 页 | 大页数不能突破协议偏移 |
| 成交量 | volume_lots 固定 wire/100 | vol 保留解码数；显式转股 | 当前显式单位设计更适合避免静默混用 |

基线 3.2.2 本身没有公开 `bar_time` 开关，本次不将它列为必须补齐的基线要求。当前单页日线时间使用固定 15:00，不意味着所有其他 SDK 的时间定义相同。

项目 `k_adjusted` 注释“通达信服务器返回均为不复权”的证据来自本库旧 38 字节请求，不能推广成所有主站或增强 052d 都不支持服务器复权。基线参数能编码，也仍需要线上验证其目标主站支持情况。

### 3.5 分时：基本价格 / 量可用，完整时间与字段不足

| 接口 | 当前字段 | 基线差异 |
| --- | --- | --- |
| minute → 051d / 0fb4 | price、vol | 未实现 0537；均价、序号、时分、来源和完整头缺失 |
| history_minute → 0fb4 | price、vol | 日期 u32 直接编码；昨收 / 辅助字段丢弃；无批量 |
| 0feb | 无 | 缺近期 selector、今开、均价及完整分时模型 |

历史分时的“均价可能缺失”也是基线 0fb4 的布局特性，不将这个缺失单独判为本项目落后。明确缺口是基线能够保留的昨收、分钟序号 / 时间、请求日期上下文、原始值和批量封装。[cite:5](#cite-5)

`history_minute(..., 20260230)` 当前没有日期真实性校验；其注释“保留约 1–2 周”也不是本轮测定的保证。当前分时价格固定 /100，多小数品种需要精度依据；当日回退用的是北京时间当天自然日，周末仍可能取不到主站最后交易日，应保留实际来源和日期判断。

### 3.6 明细：有单页数据，缺全量与事件模型

当前 `TransactionData` 为 `time/price/vol/num/buyorsell`。当日 0fc5 解析未知方向原值不丢弃；旧历史 0fb5 的 num 被填 0，因为该布局没有笔数字段。[cite:5](#cite-5)

| 基线能力 | 当前项目 | 使用影响 |
| --- | --- | --- |
| 1–1800 条/页 | 允许 1–2000 | 明确为客户端边界不同；不能仅据基线断言服务端 2000 一定非法 |
| 自动全量分页 | 无，调用者仅有 start/count | 容易只取最新一页、遗漏历史 |
| 单只 / 多证券入口 | 仅单只 | 需外层循环或有界批量封装 |
| 交易日 / 带日期时间 | 当前 DTO 没日期 | 返回时无法直接证明数据所属交易日 |
| actual_trades / auction_snapshots / opening_matches | 无 | 原始状态保留不等于正确业务分类 |
| 增强历史 0fc6 | 旧 0fb5 | 不能互换解析器；真实笔数可用性不同 |
| side / event_kind 分离 | buyorsell 原值 | 非普通方向的盘后状态不能直接丢掉 |
| 保留 raw / record 原文 | owned DTO 不保留 | 需要低层对象 / FrameObserver 留证 |

**必须补的分类顺序：**

```text
先判断 status_raw == 8             → 竞价快照，不计成交
否则时间 == 09:25                  → 正式开盘撮合
其他                               → 成交，再按状态区分盘后等情形
```

当前仅保留数字 8，没有 `is_actual_trade` 等属性，所以把所有返回量直接求和可能混入快照。056a 未接入也意味着无法取得完整竞价数量过程；不能用明细的 vol/num 猜出虚拟匹配 / 未匹配数量。[cite:1](#cite-1)

### 3.7 财务：不仅缺批量，还存在量纲与字段命名冲突

当前 `FinanceRequest` 查询单只，响应数量只允许 0/1；有日期、身份、浮点和完整长度检查。`finance()` 无数据返回 NotFound，不能直接把批量响应交给现有解析器。[cite:5](#cite-5)

**使用同一份仓库保留的真实响应原文读取 float32，再分别应用两侧源码换算：**

| 字段槽 | 原始值 | 当前 rustdx | eltdx 3.2.2 | 结论 |
| --- | ---: | ---: | ---: | --- |
| 总资产 raw | 6028785152 | 60287851520000 | 6028785152000 | 当前 ×10000，基线 ×1000，差 10 倍 |
| 原 zhigonggu / eps 槽 | 1.2400000095367432 | zhigonggu=12400.000095367432 | eps_raw=1.2400000095367432 | 当前按股本放大，基线按每股收益命名并保留 |

这不是模拟业务数据；输入为 `tests/fixtures/protocol/finance.response.hex`，差异来自源码运算。本轮没有把结果再次与发行人财报独立核验，所以结论为 **相对基线存在确定差异，需要核实后修正业务解释**。[cite:2](#cite-2)[cite:5](#cite-5)

| 类型 | 当前 | 基线 | 建议 |
| --- | --- | --- | --- |
| 股本总量 | ×10000 | ×10000 | 转换已一致，不重复放大 |
| 资产 / 利润 / 收入 / 现金流等总额 | 多数 ×10000 | 金额类原值千元，×1000 | 按字段核实原始单位，明确迁移版本 |
| 股东人数、每股净资产 | 原值 | 原值 | 不按总量比例换算 |
| 同一 EPS 槽 | zhigonggu 且 ×10000 | eps_raw | 独立核实含义、报告期与适用品种 |
| 原值保留 | 当前主要仅输出换算值 | raw_float / raw bytes | 增强模型应保留两层 |
| 本地 fields 过滤 | 无 | 有，服务器仍返回完整记录 | 可选便利能力，不是节省报文的措施 |

现有财务测试与固定旧 pytdx 期望一致，证明实现遵循原断言，**不能消除它与 3.2.2 的单位 / EPS 冲突**。财务语义应列为先核实的事项，不宜只补批量方法后就宣称兼容。

### 3.8 股本变迁：类别 1 有基础，增强类别和数量单位不齐

当前单只 Xdxr 保留 market/code/date/category 和四业务字段，但没有独立 raw / float / normalized 三层字段；类别 `1/11..14` 按 float，其他按旧数量解码，其中 **类别 15 落入数量分支**，与基线比例类解释不同。[cite:5](#cite-5)

基线类别 6 为混合价 / 发行数量，当前没有对应的专门混合分支；基线数量类别统一转换为股，当前不是同一显式转换合同。返回事件日期和身份也没有 checked 财务那样的完整校验。

补齐顺序应为：明确类别字段和单位 → 引入可保留原值的模型 → checked 请求 / 解码 → 单报文批量、前缀返回核对与补拉。本地复权只取类别 1 已有价值，不应因为基线多类别就盲目把所有事件加入复权。

### 3.9 文件：板块完整性已有，通用资源合同未实现

当前有 `02c5` 文件大小元信息 + `06b9` 分块读取，高层 `block()` 在同一持有的 Tcp 上循环，要求每块正好达到已知所需长度，文件最多 64 MiB；可以避免把不完整板块内容静默当作全文件。[cite:4](#cite-4)

| 维度 | 基线 3.2.2 | 当前项目 |
| --- | --- | --- |
| 文件路径 | 非空 ASCII≤300、拒绝 NUL | 内容名字段 100，超长直接截断；元信息名另为 40 |
| 块长 | 1–60000，默认 30000 | 低层接受任意 u32；高层固定 30000 |
| 低层结果 | FileContentChunk 包含实际长、偏移、内容、is_last | 跳过前 4 字节返回内容，没有等同字段合同 |
| 整文件 | 通用 download_file，支持 pin | 高层主要板块文件，持有同一 Tcp |
| 完整性 | 短 / 空块结束；max_bytes 到上限可能只返回前缀 | 已知文件长度，逐块要求完整 |
| 统计文件 | zhb.zip / tdxstat 两表模型 | 没有此下载解析封装 |

因此已有板块长度防护应保留。不能为复制 `max_bytes` 而引入“成功返回部分文件但无完整性标记”的语义；增强资源 API 宜明确完整 / 截断 / 预算耗尽状态。

资金流向应采用手册已核对的源码公式：`main_net` 只加超大 / 大单两项，`main_buy_net` 为四项；基线文档中“main 四项相加”的文字冲突不能复制为实现要求。

## 5. 频率、连接预算和持续采集的实现情况

### 5.1 已有预算与尚缺调度

| 能力 | 当前实现 | 对使用频率的含义 |
| --- | --- | --- |
| 进程业务连接预算 | 默认 max_connections=8；可设同机共享许可 | 限制活动连接，不限制 QPS |
| 单次 TCP I/O | 默认 5 秒 | 不是刷新间隔 |
| 请求总预算 | 默认 15 秒 | 约束请求 / 重试持续时间 |
| 建连 / 分页 / 批量预算 | 30 / 120 / 300 秒 | 已有总体时限，但不自动定期执行 |
| 失败主站冷却 | 默认 10 秒 | 避免连续选择失败主站 |
| 自动重连 | 默认 0 次，配置开启 | 默认无业务重试；开启后增请求量 |
| 重试退避 | retry_delay_ms × 失败次数，默认 0 | 线性退避，不是限流器 |
| 空结果二次确认 | 可选，默认关闭；等待 300ms 重连重查 | 可能增加一次请求和握手 |
| 主站每日筛选 | 北京时间 09:00；首次补测；每节点三轮 | 节点健康维护，不是业务采集频率 |
| 探测并发 | 最多 8 条，独立于业务许可 | 同进程可能同时有业务连接和探测连接，总 socket 不应只按 8 算 |
| 业务 QPS / 调度 | 无逐命令 QPS 令牌、频率表或定时采集器 | 手册建议频率尚需调用层实现 |
| 后台会话心跳 | 无；借出空闲连接时探活 | 长时间持有 Client 应自行保活 |

依据当前 TcpConfig、NetworkPolicy、ConnectionPool 与 IpPool；这些是代码默认值，不是官方服务端配额。[cite:3](#cite-3)[cite:7](#cite-7)

### 5.2 手册频率建议能否直接使用

| 数据 | 可用入口 | 调度现状 | 应用层需要补充 |
| --- | --- | --- | --- |
| 快照 3–5 秒 | quotes | 单次同步查询 | 非重叠轮次、分批、失败退避、日期 / 新鲜度 |
| K 线按周期 / 盘后 | bars/*_range/*_batch | 查询 / 回补已有 | 周期边界、未收完标记、增量覆盖最后一根 |
| 分时 30–60 秒 | minute/history_minute | 查询已有 | 完整字段 / 精度、确认实际日、覆盖更新 |
| 明细最新页 3–5 秒 | transaction | 单页已有 | 全量分页、事件分类、盘后补齐与去重策略 |
| 股本 / 财务每日 | xdxr/finance | 单只查询已有 | 完整批量、字段单位核实、本地版本归档 |
| 板块每日 / 文件变更 | block | 板块下载已有 | 通用资源、内容摘要、统计日期 |
| 竞价 / 推送 / 日资金 | 无 | 尚不能接该调度 | 先接协议与状态，再接持续运行 |

`src/cache.rs` 有可选内存 / 文件缓存与获取合并，但没有自动接入这些 Client 方法。缓存模块注释的推荐 TTL 不构成当前行情的实际 TTL。强制每 5 分钟才更新实时快照也不符合 3–5 秒目标，应按业务类分别配置。

### 5.3 库、CLI、runner 分开判断

| 层次 | 当前状态 |
| --- | --- |
| 核心库 | 有上述基础 TCP 查询、回补、预算、留证接口 |
| CLI | 当前子命令为 day / data-check / data-status / show，主要解析 .day / ZIP，不提供这 22 项通用命令入口 |
| runner | 冻结本地 .day 输入、执行采集 / 校验 / 发布链路；没有按 22 个 TCP 命令持续轮询的 Job |
| TCP 归档工具 | 可保存请求 / 完整压缩帧并离线解压；留证不等于推送订阅 |

当前文件采集 / 数据库发布能力有独立价值，但不能拿它证明实时 TCP 竞价、行情推送或资金流向已接成生产任务。[cite:8](#cite-8)

## 6. 补齐顺序与完成判据

| 顺序 | 范围 | 具体交付 | 完成判据 |
| --- | --- | --- | --- |
| 1 | 数据语义 | 财务单位 / EPS 核实，明细事件分类，分时日期校验，报价精度，股本类别 / 单位 | 真实原文 + 独立业务期望 + 边界验证；不只沿用旧夹具 |
| 2 | 已有合同增强 | 新目录、财务 / 股本批量、明细全量、完整分时结果、通用文件 | 请求、解码、API、批量 / 分页及缺失结果一致 |
| 3 | 常用新查询 | 054c、054b、0452、0feb | 完整布局、身份 / 日期 / 数量、可复核真实响应 |
| 4 | 实时与专用服务 | 0547、056a、0ffc | 主站能力、消息匹配、队列 / 游标、重连基线、单位与分类 |
| 5 | 辅助图 | 051b、0fd1 | selector / window 可用范围及不确定字段明确 |
| 6 | 持续采集 | 按实际产品需要接 CLI/runner | 调度、整体 QPS / 连接预算、归档、缺口 / 新鲜度、持续运行证据 |

九命令计划已对新增接口与同步有界方案作详细拆分，可复用其任务结构；已有字段语义和四项旧命令升级仍要单独纳入，不能只加九个 opcode 就判定基线完成。

若九项新增全部完成，命令集合预计从 15 增至 24，相对基线同码从 9 增至 18，剩余 `0004/044d/0537/0fc6` 仍使用替代命令。最终每项还必须有对应 API、字段、参数、失败 / 空结果、来源和目标范围验证。

项目采用同步 I/O 与有界线程已有合适基础，无需因参考 SDK 有 Rust 运行核心就引入异步运行时。新增实现应独立核实协议；基线包使用 Research-Only License，不能默认其源码可复制进 MIT 的生产项目。[cite:1](#cite-1)
