# rustdx 数据运营说明

更新日期：2026-10-22；适用本轮仓库源码。运营任务是确认行情日期、覆盖范围和计算口径，并在源故障或漏跑时安排补数。[需求说明](REQUIREMENTS.md)定义产品行为，[运维手册](RUNBOOK.md)定义部署和恢复操作。

## 数据任务

| 任务 | 用途与输入 | 成功后的判断 |
| --- | --- | --- |
| `day`目录/官网包 | 日线历史、全量或漏日回补；按业务需要筛选市场/名单 | 清单complete、退出0；核对日期边界、证券数、有效行及警告 |
| `day -g gbbq` | 基于历史日线计算累计收益指数 | 来源gbbq已记录；若为增量，前因子有效并衔接 |
| `east` | 收盘后当前行情日快照 | 数据已收盘、日期符合当前行情日；无收盘证券记录为未知 |
| `east -p factor.csv` | 以上一交易日基准接续收益 | 前因子逐证券齐全且日期是上一交易日；漏跑先回补 |
| 数据库输出 | 将已经验证的CSV写入ClickHouse/MongoDB | 再检查acknowledged及文件状态；目标库独立核对后使用 |

示例命令：

```sh
rustdx day ./vipdoc/sh/lday ./vipdoc/sz/lday \
  -o stocks.csv --report day-run.json --workers 4
rustdx day ./lday -l sz000001,sh600000 \
  -o subset.csv --report subset-run.json
rustdx east -o east.csv --report east-run.json
rustdx east -p factor.csv -o incremental.csv --report incremental-run.json
```

只在收盘后安排单个east任务，避免同出口并发扫描。实际调度由部署环境执行，库和CLI没有内置定时服务。独立任务使用独立工作目录，避免数据库中间文件 `clickhouse/mongodb`、factor.csv及报告路径冲突。

## 成功与质量判断

命令退出0且清单complete是流程成功；没有证明所有应有证券都在输出中。运营人员应将清单与本次选取的证券名单、预期行情日和历史基线对照。行数变化或空数据需核实证券状态、筛选参数和源响应，不能直接认定停牌。

日线默认告警涵盖日历覆盖外、缺口及允许保留的非A股源异常。`--strict`会拒绝这类警告；覆盖1990年以来的全量包时，内置2024–2026日历不足以支撑全历史严格验收。是否接纳告警取决于实际使用范围，不能通过删除告警声称数据完整。

A股文件重复/逆序日期拒绝发布；非A股告警在默认模式允许保留时，输出再排序并对同日保留最后一条，strict模式拒绝告警。跨输入的同证券日期区间重叠也拒绝。即使区间内缺口互补，也应先整理成一个可核实的输入，不能直接叠加重跑。

最新清单会更新，每次run_id归档提供追溯。运营审查保存原始归档，不修改状态或错误字段；异常终止的running和数据库unknown交给运维核实。状态定义及摘要范围见[IMPORTS.md](IMPORTS.md)。

## 统一口径

| 项目 | 使用规则 |
| --- | --- |
| 证券 | 保留sh/sz/bj与前导零；指数与股票同数字代码不混用 |
| 时间 | UTC+8行情日期；日历、源时间戳和收盘状态分别核对 |
| 价格/金额 | 元；历史涨跌停使用未复权分单位昨收 |
| 成交量 | 标准Bar为股；day/东财CSV为手（100股）；非A股先核实源单位 |
| factor | 累计收益指数；0表示未计算；不用于直接缩放OHLC |
| 价格复权 | 后/前复权锚定后端可用历史首/末日，可能不是上市日 |
| 指标 | RSI横盘50；KDJ使用本库EMA系数与初始化，缺口按文档处理 |
| 概念/行业 | 通达信板块按源名及采集日期保存；行业/省份编码须配合同源版本字典 |

历史策略调用日期化涨跌幅接口，提供当日ST/上市阶段；静态接口采用2026-07-06主板规则。覆盖截至2026-10-22，不包含完整证券状态历史。详细例外见[LIMIT_RULES.md](LIMIT_RULES.md)。

## 漏跑、源失败与版本变化

east源限流或TLS失败时停止本次发布，保留原成功数据并记录失败。优先用后续官网日线包或通达信历史K线补回缺失日期；逐证券核实后再接续收益。重试不得以同日快照跨越缺失交易日，也不得自动重试unknown数据库写入。

日历更新必须有交易所公告支持的完整覆盖区间，并保留版本、来源及JSON；填入2027数据前核实该区间所有休市日，前因子导航也需覆盖前一交易日。日历更新不会扩展涨跌幅规则核实范围。

本轮10月22日优化使用源码构建，crates.io安装仍是10月11日发布的1.12.2/1.8.2。对外使用说明应明确源码提交与日历/规则版本，不把历史2981万行ClickHouse验收当作本轮在线验收。发布与两个历史版本见[RELEASES.md](RELEASES.md)。

## 运营记录

每次任务保留运行标识、源码提交、选取名单、行情日、输入来源/摘要、输出行数/日期边界、质量结论和故障处置。目标库核对结果与运行清单一起保存；产物摘要不能替代源文件备份。记录保存期限由部署方确定，两个源码历史标签不限制运行归档数量。
